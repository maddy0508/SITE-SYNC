# M1.5 — QR attendance completion

## Objective
Finish the worker QR presentation and Android scanning boundary without touching M1.6 attendance mutation.

## Source of truth
- Linear MMM-33 — M1.5 Worker QR display and scan validation.
- Existing QR parser, validation service, camera state machine and duplicate-frame controller.
- M1.5 completion gate: real Android camera permission/lifecycle/scanning path, worker QR display, explicit scan result states, and Android verification.

## Confirmed defects addressed
1. Camera adapter imported a non-existent/local controller path and called `consume()` while the controller exposed `accept()`.
2. VisionCamera/barcode scanner dependencies were declared by a workflow but not actually installed/pinned in the application dependency graph.
3. No worker QR display existed.
4. No real camera permission/lifecycle/scanning component existed.
5. No parser → trusted validation pipeline boundary existed.
6. No explicit worker scan result presentation existed.

## Implementation
- Align `QrCameraFrameAdapter` with `QrScanController.accept()` and keep the adapter limited to duplicate-frame suppression.
- Add `QrScanPipeline` so untrusted raw QR text is parsed before trusted local validation is invoked.
- Add deterministic camera permission mapping.
- Add VisionCamera `CodeScanner` integration with QR-only detection, Android permission handling, foreground/background lifecycle, processing pause and explicit reset.
- Add platform-neutral QR matrix generation and worker QR identity display.
- Add valid/provisional/blocked/parse-error/camera-error result presentation.
- Pin VisionCamera 5.2.2, barcode scanner 5.2.2, Nitro modules 0.36.5, Nitro image 0.15.1 and qrcode-generator 2.0.4.
- Add focused CI verification for QR tests, TypeScript and Android debug assembly.

## Verification
1. Targeted Jest suite.
2. TypeScript `tsc --noEmit`.
3. Android debug APK assembly.
4. Device verification: valid QR, malformed QR, unsupported version, organisation mismatch, unassigned worker, offline provisional result, repeated frames, background/foreground, permission denied and permanently blocked permission.

## Explicit non-goals
- No attendance event/state mutation.
- No command ledger mutation.
- No synchronization/reconciliation.
- No production migration.

## Completion state
`implemented` pending fresh CI and Android/device evidence.
