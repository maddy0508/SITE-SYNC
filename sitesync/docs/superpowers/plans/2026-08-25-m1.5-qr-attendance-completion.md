# M1.5 — QR attendance completion

## Objective
Finish the worker QR presentation and Android scanning boundary without touching M1.6 attendance mutation.

## Source of truth
- Linear MMM-33 — M1.5 Worker QR display and scan validation.
- Existing QR parser, validation service, camera state machine and duplicate-frame controller.
- M1.5 completion gate: real Android camera permission/lifecycle/scanning path, worker QR display, explicit scan result states, reproducible dependency installation, and Android verification.

## Confirmed defects addressed
1. Camera adapter/controller contract was inconsistent.
2. VisionCamera/barcode scanner dependencies were declared in `package.json` but the committed lockfile was stale.
3. No worker QR display existed.
4. No real camera permission/lifecycle/scanning component existed.
5. No parser → trusted validation pipeline boundary existed.
6. Explicit result presentation existed but was duplicated and not wired into the scanner path.
7. Duplicate-frame suppression did not prevent concurrent asynchronous processing.
8. The app shell stored raw QR text without trusted validation context; it now fails closed instead.
9. CI previously used `npm install` and a scanner-launch smoke test that did not prove the QR processing boundary.

## Implementation
- Align `QrCameraFrameAdapter` with `QrScanController.accept()` and expose an explicit release/reset boundary.
- Make `QrScanController` reject all additional frames while asynchronous processing is active; retain the 750 ms duplicate window as secondary debounce.
- Add `QrScanPipeline` so untrusted raw QR text is parsed before trusted local validation is invoked.
- Add deterministic camera permission mapping.
- Add VisionCamera barcode integration with QR-only detection, Android permission handling, foreground/background lifecycle, processing pause and explicit reset.
- Ensure every accepted frame releases the processing claim on success, failure, cancellation, or lifecycle reset.
- Add platform-neutral QR matrix generation and worker QR identity display with a four-module quiet zone.
- Keep one scanner-owned result presentation path; remove the unused duplicate result panel.
- Make the application shell fail closed when no authenticated/trusted QR validation context is injected; raw QR values are never persisted or displayed as accepted results.
- Synchronize `package-lock.json` with the actual dependency graph and use `npm ci` in CI.
- CI now runs the full Jest suite and full TypeScript check before Android assembly.
